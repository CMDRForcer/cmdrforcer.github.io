Connection controls

Know what is shared

ED-Frame and EDDN community services are enabled for new profiles and can be disabled in Connections. Our server accepts supported public observations, not Commander identities, raw Journals, private builds or credentials.

Freshness follows the original observation time. Coverage depends on reported activity; prices, stock, yield and merits are not guarantees. Read the 1.0 guide and privacy details · Deutsche Anleitung

Why ED-Frame

Most build tools model a type of ship.
ED-Frame models your ship.

The specific hull with its ShipID, physical module slots and current Loadout — then connected to the rest of your Commander state: materials, Engineer access, routes, credits, fleet, signals and scans.

A plan stays attached to the slot, so two identical Multi-cannons never get confused. ED-Frame separates observed facts, planned work and predictions instead of presenting guesses as certainty. And you can plan for a ship parked across the bubble without switching to it in-game.

Frequently asked.

Is ED-Frame free?+

Yes. ED-Frame is free and open source under the GNU GPLv3 license, with no ads and no paid tier. You can also read every line of the code it runs.

Does ED-Frame upload my data anywhere?+

ED-Frame and EDDN community connections are enabled by default for new profiles and can be disabled in Connections. They support public observations; our server does not accept Commander names/FIDs, raw Journal files, private builds or credentials. Frontier CAPI and INARA require separate setup. Your local Commander data and retained observations remain on your computer. Read the connection and privacy details.

Does ED-Frame count active installations?+

Release builds automatically count active installations with a random UUID4 installation ID and the app version. The random ID remains recognizable across days. At most one ping is sent per UTC day while the ED-Frame catalog is enabled. The same ID is used for all Commander profiles; it is not a hardware ID. The database stores only ID, UTC day and version and deletes entries older than 90 days daily. It stores no IP addresses. No Commander names/FIDs, Journals, gameplay events or screen/activity data are sent. Existing server access logging stays unchanged. There is no dedicated counting switch; Settings → Connections and onboarding explain the data sent. Disabling the ED-Frame catalog or setting EDFRAME_NO_USAGE_PING=1 prevents pings. Development builds never ping; failed days are not replayed. You can view and copy your ID in Settings → About. Installation statistics are private and are not shown on this website.

Can I run ED-Frame alongside EDMC?+

Yes. Both read the same local Journal files independently and read-only, so there's no file conflict. If you enable EDDN uploads in both, each sends its own copy of the same events — harmless but redundant, so leave that switch on in only one of them.

Do I need to create an account?+

No account is required to use ED-Frame. Signing in to Frontier CAPI or INARA is only needed if you choose to enable those optional integrations.

What platforms and languages does ED-Frame support?+

ED-Frame runs on Windows 10 and 11, with the interface available in English, German, Spanish and French.

How do updates protect my plans?+

Install 1.0.11 manually once; earlier releases have no updater. Quit the old app and extract the complete ZIP into a new folder. Existing profiles and plans are reused from the separate AppData folder. Future compatible releases appear in Settings → About, with optional background downloads and installation after you choose Update and restart. The updater verifies the package, backs up all local profiles and keeps the previous app. Failed replacement or startup restores the old app and profile snapshot. Backups and previous program folders remain available and take additional disk space. Release builds check GitHub at most once per UTC day independently of the catalog connection, without sending installation IDs or Commander/Journal data. Disable automatic checks in About or set EDFRAME_NO_UPDATES=1 to disable all checks.

Why is 1.0 newer than the older 1.5 releases?+

1.0 starts the new public ED-Frame release line and succeeds the earlier EDEC/ED-Frame builds, including 1.5.43. Historical Git tags preserve the version history; releases marked outdated and their downloads are removed from GitHub. Use the current download link instead of sorting the old version numbers.
